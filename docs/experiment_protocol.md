# 实验协议、指标与结果分析（v2）

## 1. 实验对象

比较 Rule-based、Q-learning、DQN、Double DQN 四种纵向控制策略。Rule-based 为非学习基线。四种方法调用同一个 `IntersectionEnv`，采用相同的观测、动作、交通密度和评估流程。

## 2. 训练协议

| 项 | v2 默认 | 说明 |
|---|---|---|
| 训练回合数 | 600 | `--episodes` |
| 训练密度 | mixed | 每回合在 low/medium/high 中均匀随机；`extreme` 不参与训练 |
| 训练路线 | straight / left / right | 每回合均匀随机；`--routes straight` 为仅直行训练 |
| 训练种子 | 42（建议 42 43 44） | 每个种子独立训练一次，`--seeds` |
| ε 衰减 | auto | 在 70% 回合内降到 0.05，之后保持 |
| 环境种子 | `100000 + 种子×10000 + 回合号` | 与测试种子隔离 |

训练日志 `results/<algo>/seed_<S>/training_log.csv` 含每回合的 density、ego_route、reward、steps、loss（仅 DQN 类）、epsilon、通过/碰撞/闯红灯/超时标记。

**设计依据：** v1 只用单一密度、单一路线训练 300 回合、ε 终值 0.22，导致（a）训练分布与评估分布不一致，（b）策略在训练结束时仍含大量随机动作，（c）单次训练无法估计训练随机性。v2 对应地改为混合场景、ε 降到下限、多训练种子。

## 3. 评估协议

`evaluation/common.py` 中的默认设置：

| 参数 | 默认值 |
|---|---|
| 每个密度/路线回合数 | 50 |
| 最大步数 | 300 |
| 测试 seed 起点 | 1000 |
| 密度 | `all` = low / medium / high；`all+extreme` 另加 2.0 倍压力测试 |
| 路线 | straight / left / right（`--route all`） |
| 动作数 | 5 |
| 停车阈值 | 0.1 m/s |
| 急刹阈值 | −3.0 m/s² |

每个算法对给定组合使用相同 seed。正式对比应保证评估回合数、最大步数、密度、路线、seed 起点、模型选择规则均一致。评估使用贪心策略（无探索）。

**结果合并保存：** 同一目录下的 `evaluation_episodes.csv` / `evaluation_summary.csv` 按 (algorithm, density, ego_route) 合并，重复评估同一组合时只替换该组合；`--overwrite` 才会整体覆盖。

## 4. 指标定义

| 指标 | 定义 | 解释 |
|---|---|---|
| mean_reward | 每回合累计奖励的均值 | 综合奖励目标；**主要由步数决定**（见第 7 节） |
| std_reward | 回合奖励标准差 | 场景间波动 |
| safe_pass_rate | outcome 为 passed 的比例 | 无碰撞、无确认闯红灯、无传送且成功通过 |
| collision_rate | 至少发生一次碰撞的比例 | 碰撞风险 |
| red_violation_rate | 确认闯红灯的比例 | 信号遵守情况 |
| timeout_rate | 未通过且达到最大步数的比例 | 通行失败/超时 |
| mean_pass_time_s | 成功回合的首次通过时间均值 | 通行效率 |
| mean_speed_m_s | 回合平均速度的均值 | 行驶速度表现 |
| mean_stopped_steps | 速度低于 0.1 m/s 的步数均值 | 停车等待 |
| mean_hard_brake_steps | 实际加速度不大于 −3 m/s² 的步数均值 | 急刹行为 |
| min_leader_gap_m | 所有记录中最小前车间距 | 诊断性跟车指标 |

安全通过率、碰撞率和红灯违规率提供 Wilson 95% 置信区间。多个训练种子时，`evaluation.aggregate_seeds` 报告**训练模型之间**的均值与标准差（`*_std` 列），它包含了训练随机性，是写报告时应使用的不确定性度量。

## 5. 统计检验

不同算法在相同测试 seed 下运行相同 SUMO 场景，因此结果是配对样本。`evaluation.compare_algorithms` 使用：

- 累计奖励：双侧 Wilcoxon signed-rank 配对检验；
- 通过时间：双侧 Wilcoxon 配对检验，仅保留双方均成功通过的 seed；
- 安全通过：精确配对二项检验（McNemar 检验的条件形式）；无不一致回合时 p = 1；
- 多重比较：对全部检验 p 值进行 Holm-Bonferroni 校正。

显著性阈值为校正后 p < 0.05。**统计显著不等于实际效果足够大**，v2 增加 `practically_meaningful` 列：校正后显著且中位数差超过 `--min-reward-diff`（默认 0.3）/ `--min-time-diff`（默认 2.0 s）。阈值是研究者的判断，应在报告中说明取值依据。

配对检验只比较**一个训练种子**的模型（`--train-seed`，默认最小种子）。跨训练种子的结论应基于 `multi_seed_summary.csv`。

## 6. 可视化

`python -m visualization.plot_results` 输出的图表清单见 README 第 10 节。要点：

- 多训练种子时柱状图为均值±标准差，训练曲线为均值与 ±std 阴影带；
- 安全通过率始终绘制（含 Wilson 区间），其余失败类指标合并为一个面板，全为 0 时给出文字说明；
- 三种算法 ε 衰减相同时只画一条线，不再出现“被覆盖”的曲线；
- `route_generalization.png` 并排比较直行/左转/右转。

## 7. 结果解释的边界

- **奖励的结构：** 成功通过 +50，前进奖励总量近似固定，每步 −0.05，急刹 −0.1。对 v1 数据的线性拟合为 reward ≈ 73.3 − 0.058×steps（残差标准差约 0.2）。因此在不发生碰撞/违规时，奖励几乎等价于“通过所用步数”，并有物理上限（约 72.5）。奖励接近上限说明策略已经通过得足够快，不代表训练卡住。
- **安全天花板：** 当通过率全为 100% 时，安全指标无法区分算法。应使用 `extreme` 密度、更多回合，并以效率/舒适指标和多训练种子分析。
- **Double DQN 的优势在于缓解 Q 值过估计**，在奖励稀疏、噪声大、动作多的任务中才明显；本任务动作少、奖励稠密，预期差异较小。没有观察到差异本身就是有效结论，但需要多种子支持。
- 相同测试 seed 只控制评估场景，不代表不同算法训练过程相同；单次训练得到的模型不足以刻画训练随机性。
- 当前主车路线在回合开始前指定，动作仅控制纵向加速度，观测中不含路线信息；不能将结果表述为完整的自主路线选择。
- `extreme` 密度（2.0 倍）未经过 `docs/calibration.md` 的标定，只作为相对压力测试。
- 最小前车间距接近 0 时，应复核具体逐回合轨迹、车辆长度、车道与 SUMO gap 语义。
- 仿真结果不能直接等同于真实道路部署效果。
